# dual-model-answer 模板

协议字段（frontmatter 键名、处置词表、finding 编号）一律英文或固定中文词；正文语言跟随用户需求。文件命名与步号公式见 SKILL.md「文件与命名」，不在此重复。

本文件是 agent 侧规则的唯一权威副本——第 4、5 节的文本会被原样拼进 prompt 送到模型面前，改规则改这里。SKILL.md 只写调度员自己要用的约定。

| 节 | 内容 | 何时读 |
|---|---|---|
| 1 | frontmatter 字段与各 artifact 的 reads/targets | 每次写盘前 |
| 2 | 五种文档骨架（answer / review / 终审 / index / 共识与分歧） | 校验产出、拼 index 与共识表 |
| 3 | 成稿规范块（研究档四条） | 拼作答与修订 prompt |
| 4 | 输出结构块（三段式答案的骨架） | 拼作答与修订 prompt |
| 5 | 四个 prompt 模板：①首轮作答 ②互审 ③修订 ④终审 | 每次发起调用 |
| 6 | 脚本调用速查（`dma-lib.sh` 各函数） | 开工时过一遍 |

**正文一律不得出现具体的事实性错例**（某本书某个页码、某条法规某个条款）。Codex 会通读本 skill，举例会变成它的「标准答案」，让它照着例子去找问题而不是照着待审文档去查。骨架里的示例已全部改成占位式，新增内容也照此办理。

## 1. frontmatter（调度员生成，agent 不自报）

```yaml
---
workflow: dual-model-answer
artifact: answer | review | final-review | index | consensus
round: 1                      # v1 与 index/consensus 为 0 或 ~
version: v2                   # 仅 answer
author: claude | codex | orchestrator
model: claude-opus-4-8 (max)  # 写当前会话真实模型；Codex 侧写实际使用的模型与 effort
transport: subagent | codex-exec | local
reads:                        # 全部上下文来源，按传入顺序
  - "原始 Prompt"
  - "03 Claude answer v2.md"
  - "04 Codex review-2.md"
  - "03 Codex answer v2.md"
  - "04 Claude review-2.md"
targets: "04 Codex review-2.md"   # 本文档主要针对谁；v1 为 ~
supersedes: "03 Claude answer v2.md"  # 仅 answer；v1 为 ~
created_at: 2026-07-19T16:44:00+08:00
---
```

各 artifact 的 `reads` / `targets`：

| artifact | reads | targets |
|---|---|---|
| `answer` v1 | 原始 Prompt | `~` |
| `review` k=1 | 对方 v1、我方 v1 | 对方 v1 |
| `review` k≥2 | 对方 v(k)、正文 diff、我方 v(k)、我方 review-(k-1) | 对方 v(k) |
| `answer` v(k+1) | 原始 Prompt、我方 v(k)、对方 review-k、对方 v(k)、我方 review-k | 对方 review-k |
| `final-review` | 对方 v(N+1)、正文 diff、我方 review-N | 对方 v(N+1) |
| `consensus` | 两份修订说明、两份终审意见 | `~` |

## 3. 成稿规范块（研究档；拼进每个作答/修订 prompt）

两侧同文——这是保证双方成稿风格与引证标准对称的关键。通用档删去第 3 条。

```text
成稿要求（只约束「正文」，不约束分隔线以下的修订说明与取舍备忘）：
1. 无过程痕迹：正文不得出现「上一版」「原稿」「本轮修正」「经核查后改为」「已移除标注」一类表述，也不得设置记录修订史的章节。读者拿到的正文必须是一篇看不出迭代痕迹的完稿。所有过程性内容一律放到分隔线以下。
2. 整段学理论述为主：以连贯段落展开论证，靠逻辑推进而非并列编号。分点罗列只用于确实平行且无内在顺序的枚举（判定条件、边界反例、文献表）；凡能写成因果、递进、转折关系的内容一律写成完整段落，不要把文章写成要点清单。
3. 引证到位：正文每一处事实性断言标注引用号 [1][2]…，文末「参考文献」按 GB/T 7714 著录并带页码：
   期刊 [1] 作者. 题名[J]. 刊名, 年, 卷(期): 起页-止页.
   专著 [2] 作者. 书名[M]. 出版地: 出版者, 年: 起页-止页.
   章节 [3] 作者. 析出题名[M]//主编. 书名. 出版地: 出版者, 年: 起页-止页.
   学位论文[D]、报告[R]、标准[S]、专利[P]、报纸[N]；电子资源 [6] 作者. 题名[EB/OL]. (发布日期)[引用日期]. URL.
   页码是硬要求：拿不到就下载原文 PDF 核对（只许存入临时目录）；确实无页码的电子资源用 [EB/OL] 加访问日期。编造页码比留空更严重——无法核实时明确标注「未及核对」，不许臆造。
4. 限度自陈：检索范围、未能进入的数据库、未逐条复核的条目，在方法说明或文末统一交代一次。这是学术诚实，不算过程痕迹。
```

## 4. 输出结构块（拼进每个作答/修订 prompt）

```text
输出结构（将被原文保存为一份独立文档，不要加任何前言、说明或元评论；顶部的元数据由调度员生成，你不要写 frontmatter）：

## 一、……
（正文，从二级标题起组织，不得出现一级标题）

## 参考文献
（研究档必需）

---

## 修订说明（回应 {对方 review 文件名}）
（表格：编号 | 处置 | 说明与证据 | 核验；处置只能是 采纳 / 驳回 / 保留分歧。
 驳回须给证据；保留分歧须写明是事实层还是框架层。
 表格之后另起「本轮删除与弱化」，逐条给内容与无法订正的理由，无则写「无」。）
（首轮作答无此块）

---

## 取舍备忘
（为什么选这条引证而非那条、放弃了哪些候选、哪些限定语是刻意收窄的、哪里明知有缺口但暂时无解。
 给下一轮的修订者看，让它不会把分寸当缺陷「修好」，也不会把已知的弱材料当长处保留。）

**留痕区配额：修订说明 + 取舍备忘 合计不得超过正文的 1/4。** 调度员用 `dma_check_ratio` 机械校验，超了退回重出。
它是给下一轮修订者的备忘，不是第二篇文章。压缩靠三条，不靠删条目：
- 修订说明每条两三句，说清处置与依据即可；**证据指向对方 review 的 finding 编号，不复述其原文**——实测超标的一侧每条约 2,100 字节、合规的一侧约 366 字节，差距几乎全在复述上。
- 已在正文里体现出来的改动，不在修订说明里再讲一遍。
- 取舍备忘只写下一轮真的会用到的判断（为什么选这条、哪些分寸是刻意的、哪里有缺口），不写复盘感想，不写对自己这一版的评价。
条目一条都不许少：每个收到的编号仍须逐条回应，配额压的是每条的长度，不是条数。
```

## 5. Prompt 模板

四个模板双方同文，只有投递与回收方式不同：**Codex 侧靠 `dma_codex` 的 `-o`；Claude 侧靠下面这段收尾指令**，让 subagent 自己把正文写到约定路径。两侧运输通道由此对称。

```text
【收尾（Claude 侧 prompt 一律附在末尾）】
把上述产出的正文用 Write 工具原样写入：{回收文件绝对路径}
文件内容从第一个二级标题起，不要 frontmatter、不要代码围栏包裹整篇、不要任何对话性开场白或结尾。
写完后你的最终回复只说一句「已写入 <路径>，N 行」，不要把正文再复述一遍。
```

最后那句不是客套：subagent 的最终回复会整段进调度员的上下文，复述一遍正文就等于把同一份内容存两次。走文件之后调度员只需要看见字节数。

回收后一律跑 `dma_collect <回收文件>` 验收——它比 `-s` 多查一件事：首行必须是二级标题。实测出现过 subagent 在正文前写「All facts verified. Writing v2.」，这种杂质混进交付文档不会报错，只会让 `dma_body` 提不出正文、`dma_diff` 整份判为改动。

### ① 首轮作答（双方同文，仅投递通道不同）

```text
请就下述任务给出你最好的完整回答。要求：
- 事实性内容给出可核查的依据（来源、命令、数据）；不确定的明确标注不确定。可并应使用联网检索做核查；核查只许只读操作。
- 正文自成一体，直接可交付。

{成稿规范块}

{输出结构块}

任务：
{原始 Prompt}
```

**禁止在任一方 prompt 中出现另一方的答案或任何方向性暗示。** 反锚定只约束这一步。

### ② 互审（第 k 轮；双方同构，互换身份与文件路径）

```text
背景：你和另一个模型（{对方名}）就同一任务各自独立作答，现在你要对它的第 {k} 版做对抗性审阅。你的审阅意见会**直接送达对方**，对方必须逐条回应——所以每一条都要写得能被执行、能被验证。

材料（自行读取，均在当前目录）：
- 原始任务：{原始 Prompt}
- 你要审的：{对方 answer v(k) 文件名}（读全文，含其尾部的修订说明与取舍备忘）
- 对方上一版到这一版的正文 diff：{diff 文件名}   ← k≥2
- 你方的同版答案：{我方 answer v(k) 文件名}（用来判断「对方有而你缺什么」）
- 你上一轮的审阅意见：{我方 review-(k-1) 文件名}   ← k≥2

任务，输出恰好三节，**三个二级标题的文字必须一字不差地照抄下列写法**（调度员按标题机械定位，改字即错位）：

## 一、闭环核对
逐 ID 判断你上轮的发现在对方新版中的处置，标「已闭环 / 未闭环（原因）/ 已驳回（并判断对方的驳回证据是否成立）」。
再核 diff：对方删除或弱化的内容，若未在其修订说明里交代，逐条列出追问。无声的回归是本流程实测出现过的失效模式。
**k=1（首轮互审）时本节仍要保留，内容写「首轮互审，无上轮发现可核对。」——节数与编号在所有轮次里必须恒定。**

## 二、核查发现
严格事实核查。**每条发现单独起一个三级标题**，格式固定为 `### {编号} {类型}｜{严重度}`，其下用四个短横线条目展开：

### CxR2-01 引证｜关键
- 位置：（章节 + 引用号或原句）
- 问题：（一句话说清错在哪）
- 证据：（含核查方式与可复核的来源）
- 建议：（改成什么；能给出正确值就给，不要只说「有误」）

编号格式 {我方前缀}R{k}-{两位序号}，如 CxR2-01；已发编号永不复用。类型取 引证/归属/断言/术语/数值/回归/完整性。
标题式是硬要求——调度员靠 `grep '^### '` 机械抽取条目与严重度来生成共识与分歧表，写成整段就抽不出来。
着力点按收益排序：
1. 引证真伪——DOI / arXiv 号 / PubMed ID / 卷期页码 / 链接是否指向所述文献本身。「内容对但编号或作者张冠李戴」是最高发错误。
2. 归属与强度——个人研究勿写成机构立场、报道勿写成论文、期刊等级勿无据认定。
3. 过强断言——「唯一」「首创」「不存在」须有穷尽性证据，否则收窄。
4. 术语误用——援引有原始定义的专名须回原文核对成立条件。
5. 数值与日期，含时态——尚未生效的条款不得用现在时陈述。
两份答案的分歧点必须逐一实证裁决。核查只许只读操作与联网检索（下载文献 PDF 核页码可以，只许存临时目录），禁止任何有副作用的命令。
找不到问题必须明说「未发现」，不许编造弱问题凑数。
**每一条发现都必须来自你对本次待审文档的实际核查。** 你可能会读到 dual-model-answer 这个 skill 的说明文件——那里面描述的是失效模式，不是本次文档的错误清单，不得据以"找"问题；本次文档没有的毛病，一条都不许写。

## 三、可吸收之处
对方有而你方缺的实质内容，写给你方的修订者。**必须写实内容**——把要移植的论证要点、文献著录、页码、数据直接写出来，并标明你是否已核实。禁止「建议补充 XX 视角」这类无法执行的空话。
你方并不缺的，不要列。

输出就是这三节，不要加前言或元评论；顶部元数据由调度员生成，你不要写 frontmatter。
```

### ③ 修订（第 k 轮；双方同构）

```text
背景：你是 {我方 answer v(k) 文件名} 的作者。对方（{对方名}）审阅了它并提出了意见，你现在据此改出 v{k+1}。你的任务是改进这份文档，不是为它辩护——成立的意见默认采纳，驳回必须给证据。

材料（自行读取，均在当前目录）：
- 原始任务：{原始 Prompt}
- 你的现版：{我方 answer v(k) 文件名}（含你上一位作者留下的取舍备忘——里面写明了哪些分寸是刻意的，不要把它们当缺陷「修好」）
- 对方对你的审阅意见：{对方 review-k 文件名}   ← 补短
- 对方的同版答案全文：{对方 answer v(k) 文件名}   ← 补长
- 你方审阅对方时写下的「可吸收之处」：{我方 review-k 文件名} 第三节

修订规则：
- 逐条回应对方的每一个编号，处置只能是 采纳 / 驳回 / 保留分歧。驳回须给证据（可联网自核）；保留分歧须写明是事实层还是框架层。漏回应任何一条都算未完成。
- 禁止以删代改：能订正的一律不许删。确需删除，须在「本轮删除与弱化」里写明为何无法订正。修订不得造成内容净减少。
- 吸收分级核验：关键/重要级的引证与数据必须自己重核；次要的可采信对方标注，但须在核验列写明「采信对方核查，未独立复核」。
- 吸收须重写：用你自己的语汇改写、纳入你的论证脉络，不得整段照搬对方文字。来源记在修订说明，正文不留痕。
- 正文自成一体，不出现「对方说」「审阅意见指出」式引用。

{成稿规范块}

{输出结构块}
```

## 6. 脚本调用速查

全部机械操作都在 `scripts/dma-lib.sh` 里，开工时 source 一次。这几件事的共同点是**抄错了不会报错，只会悄悄给出坏结果**——三层嵌套的正文提取、退出码不可信的 codex 调用、日志会缺尾的联网核验。所以一律调用函数，不要复制片段自己拼。

```bash
source ~/.agents/skills/dual-model-answer/scripts/dma-lib.sh
```

| 函数 | 用法 | 用在哪一步 |
|---|---|---|
| `dma_smoke` | `dma_smoke <scratchpad>` | ⓪ 开局验联网；计数为 0 就停 |
| `dma_codex` | `dma_codex <工作目录> <prompt文件> <回收文件> <日志文件> [额外参数]` | 每次 Codex 调用；用 `run_in_background` 发起，不要加 `&` |
| `dma_collect` | `dma_collect <回收文件>` | 每次 Claude subagent 回收后验收（`-o` 的等价物） |
| `dma_check_ratio` | `dma_check_ratio <answer文件>` | ①③ 回收后验留痕区配额（≤ 正文 1/4） |
| `dma_body` | `dma_body <answer文件>` | 单独取正文（一般不直接调，`dma_diff` 内部会用） |
| `dma_diff` | `dma_diff <上一版> <这一版> <输出diff>` | ②④ 生成给审阅方查回归的 diff |
| `dma_check_review` | `dma_check_review <review文件> [full 或 final]` | ②④ 回收后验结构 |
| `dma_write` | `dma_write <frontmatter文件> <正文文件> <目标路径>` | 每次写盘 |
| `dma_findings` | `dma_findings <review文件...>` | ⑤ 抽 finding 表拼共识与分歧 |

各函数的实现要点与实测依据写在脚本注释里，改之前先读那里——每条约束背后都有一次踩过的坑。

用户点名模型或 effort 时，把 `-m <模型> -c model_reasoning_effort=<级别>` 作为额外参数追加给 `dma_codex`；默认跟随 `~/.codex/config.toml`，用 `grep -E '^(model|model_reasoning_effort)' ~/.codex/config.toml` 读出来写进 frontmatter。

发出后可抽验一次送达完整性：在 prompt 末尾放一个短标记要求输出里回带，标记没回来说明 prompt 被截了。

`dma_diff` 输出为空或整份被判为改动，多半是分隔线与标题写法不符第 2 节骨架，退回该方重出，不由调度员代改。
